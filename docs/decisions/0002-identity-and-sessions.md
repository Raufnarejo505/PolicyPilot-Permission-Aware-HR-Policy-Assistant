# 0002 — Server-side identity and revocable sessions

Date: 2026-10-19
Status: implemented; human authorization-test review and identity design approved in conversation

## Approval and scope

The user explicitly confirmed reviewing and approving `tests/authorization/test_authorization.py` and the proposed SQLite + Argon2id + opaque revocable server-side session design. This satisfies the identity implementation gate; it does not approve corpus licensing, evaluation overrides, or model/provider/budget choices.

## Decisions

- Use standard-library SQLite, explicit schema version 1 initialization, parameterized SQL, per-operation connections, transactions, and foreign keys. SQLAlchemy is not required for this small repository. Newly created database files are mode 0600. Existing files are not chmodded; operators must secure existing directories/backups. Unknown schema versions fail closed. No default users or automatic database creation on requests.
- Hash passwords with pinned `argon2-cffi`, Argon2id v19, 64 MiB memory, three iterations, four lanes, 16-byte random salt, and 32-byte hash (RFC 9106 low-memory profile). Provisioning requires 12–1024 UTF-8 bytes without silent truncation. Verification rejects unexpected cost profiles; future hash/profile migration needs an explicit change. Unknown usernames undergo dummy hash verification.
- Issue 256-bit cryptographically random opaque bearer tokens. Store only SHA-256 token digests, user references, and expiry. The approved opaque design replaces the implementation plan's proposed JWT. Random opaque tokens need no signing secret, issuer/audience claims, or permission-version claims: the store is the authority, and possession of a live token authenticates its referenced user. No cookies, refresh tokens, public registration, seeded personas, or model tools.
- Default absolute TTL: 3600 seconds, configurable from 60 through 86400. Expiry is inclusive (`now >= expires_at` denies), with no sliding renewal. Retain at most ten sessions per user; a new login evicts the oldest insertion beyond that cap. Login-attempt transactions prune expired sessions.
- Every authenticated request checks the session and independently resolves the current enabled user from the server store. Grant/role edits increment the permission version and take effect on the next request, without forcing relogin. Password reset and enable/disable changes revoke all sessions atomically. Deleted users deny. Session creation checks the verified password hash and enabled state atomically against password-reset/disable races.
- `POST /api/v1/auth/login`, `GET /api/v1/me`, and `POST /api/v1/auth/logout`. Login is JSON; extra fields are rejected rather than interpreting client roles/grants. Logout is idempotent for well-formed already-revoked/expired tokens. No public permission-management route. `/me` returns only the authenticated user's current permissions/roles/version.
- SQLite-backed, epoch-aligned fixed-minute login budgets: five per username, ten per caller address, thirty globally. Successful and failed admitted attempts count before password verification; denied attempts consume no further budget. Throttle records use SHA-256 digests, not raw usernames/addresses, and persist across restarts/workers. Caller identity comes from ASGI connection metadata, never forwarded headers read by application code. `make run` disables Uvicorn proxy-header processing. These are conservative demo safeguards, not evaluated production rate limits; shared NATs/proxies share caller budgets, known-user lockout and distributed exhaustion remain possible.
- Authentication request bodies are bounded to 4096 bytes before JSON parsing, including chunked bodies. Validation errors never reflect submitted values. Credential, session, disabled/deleted-user, corrupt-store, and store-failure denials are generic. Auth responses use `Cache-Control: no-store` and do not set cookies. Credentials and issued-session dataclass representations redact secrets. Application code adds no credential/token logging.
- Trusted local `python -m policypilot.manage` commands initialize storage, create users, replace access, enable/disable users, and reset passwords. Passwords are entered interactively with confirmation, not command arguments or default credentials.

## Validation and deployment limits

Tests exercise real SQLite persistence and ASGI requests, Argon2 verification, corrupt metadata, current permission changes, forged claims, expiry/revocation/deletion, fail-closed store errors, login race rejection, throttling, body limits, redaction, session bounds, and local operator commands. Existing authorization tests remain unchanged. Passing tests is not proof of universal security or completion of SEC-01…10 evaluation.

This is a local/demo milestone, not production deployment approval. Enforce HTTPS, trusted ingress/proxy configuration, connection deadlines, Argon2 concurrency limits sized for 64 MiB per verification, filesystem/backup protection, and operational monitoring before external deployment. The shared global budget still permits denial of new logins from enough callers. No network calls, corpus ingestion, paid model calls, retrieval, response caching, frozen evaluation work, or UI are included. New schema additions within this milestone target fresh version-1 stores; no previously released identity database exists or is migrated.
